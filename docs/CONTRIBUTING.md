# 贡献指南（Contributing）

感谢你对 todo-cli_68 的关注与贡献。本文件说明项目的分支协作、提交信息与 Issue / Pull Request 流程。

## 一、分支规范

- `main`：主干分支，保持可运行、可发布的稳定状态；
- `feature/xxx`：新功能开发分支，例如 `feature/filter-pending`；
- `fix/xxx`：问题修复分支，例如 `fix/storage-encoding`；
- 功能开发完成并通过测试后，再合并回 `main`，不在 `main` 上直接进行大段修改。

## 二、开发流程

1. 从最新的 `main` 拉出功能分支；
2. 在功能分支上开发、提交并本地运行测试；
3. 发起 Pull Request 合并回 `main`；
4. 若合并时与主干产生冲突，在分支上解决冲突、提交后再合并。

## 三、提交信息规范

提交信息尽量清晰、可追溯，建议使用简洁的祈使句，例如：

- `add: 支持按编号删除待办事项`
- `fix: 修复 JSON 文件中文编码问题`
- `docs: 补充 README 使用示例`
- `test: 补充存储模块单元测试`

## 四、Issue 与反馈

- **问题反馈**：请说明运行环境、复现步骤、预期结果与实际结果；
- **功能建议**：描述使用场景、期望功能与价值；
- 讨论达成一致后再开发，避免重复劳动。

## 五、代码与测试要求

- 遵循现有代码风格，保持命名清晰；
- 新增功能需补充对应单元测试；
- 提交前在本地运行：`python -m unittest discover -s tests -v`。
